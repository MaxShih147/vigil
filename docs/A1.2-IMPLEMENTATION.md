### 1.2 五個硬指標
| 指標 | 公式 / 定義 | 統計基準 | 目標 |
|---|---|---|---|
| **ACC** | (TP+TN)/全部 | 每類瑕疵 ≥300 張測試影像,不含訓練集 | ≥ 90% |
| **FPR** | FP/(FP+TN),正常被誤判為瑕疵 | 正常/瑕疵樣本平衡、各類 ≥100 筆 | ≤ 10% |
| **FNR** | FN/(FN+TP),瑕疵未被偵測 | 四類:翹邊/缺層/反射過曝/材料不足 | ≤ 10% ⚠️ 現況 11.54% |
| **參數自適應時間** | 偵測→建議→調整完成之耗時 | n=20 次連續列印取平均 | ≤ 5 秒 |
| **調整後成功率提升** | AI 介入 vs 基線成功率 | ≥50 次列印、同模型重複 10 次、材料相同 | ≥ 20% |

測試條件(全指標共用):**固定硬體(含鏡頭/感測器架設位置)、影像經 3A 校正前處理、固定 batch size 推論。**

## 2. vigil 方向定調

### 2.1 兩段式:幾何觸發 + 學習分類
a1.2 要驗收的是「模型」,但 vigil 的價值在幾何管線。定調為**兩段式**,各司其職:

```
[幾何前級 L0–L3]                    [學習後級 L4 = a1.2 的模型]
cycle lock → phase-locked capture   EfficientNet-B0 五分類
→ 剪影/面積/成長性(OpenCV)         (normal + 翹邊/缺層/反射過曝/材料不足)
      │                                    │
      ├─ 產出「已對齊 layer frame」───────►│ 分類 + 信心度
      ├─ 弱標籤(自動預標,人工覆核)      │
      └─ 觸發(可疑才送模型,省算力)      └─ debounce(k=3)→ event
```

- **幾何前級**:免費產出已對齊影像、自動弱標註、當觸發器。→ 解決 a1.2 最大缺口「300 張/類」的資料來源。
- **學習後級**:單一 EfficientNet-B0 五分類模型,**這顆就是 a1.2 送驗的模型**,ACC/FPR/FNR 都量在它身上。

**為何不是純幾何、也不是純模型:** 純幾何無法產出 a1.2 要的「訓練模型 + ACC/FPR/FNR」;純模型則需海量人工標註且無法解釋。兩段式讓幾何層把標註成本壓到最低、把模型推論次數壓到最少,同時滿足查核點對「模型」的要求。

### 2.2 五分類設計(不是二元)
類別 = `{normal, 翹邊, 缺層, 反射過曝, 材料不足}`。
- **ACC** 量五分類整體正確率。
- **FPR/FNR** 用二元塌縮:normal vs any-defect。
  - FPR = P(判為瑕疵 | 實際 normal)
  - FNR = P(判為 normal | 實際瑕疵)
- **反射過曝獨立成一類是策略核心**:把「反光假影」明確學成一類,而非讓它污染其他瑕疵類 → 這是壓低 FPR 的主戰場,也對應 vigil 原本「區分 failure vs reflection」的設計。

### 2.3 模型輸入
`inspector` 的 phase-locked layer frame → 取 plate ROI crop → **固定參數 3A 正規化** → resize 224×224 → 模型。crop 與 3A 都在推論與訓練用同一份前處理,確保訓練/測試/上線一致。

### 3.1 系統三層(vigil-phrozen)
```
┌─ Machine ────────┐   ┌─ Edge: Jetson Orin Nano ───────────────┐   ┌─ Cloud ──────┐
│ Phrozen 牙科印表機 │   │ recorder ─(ffmpeg tee)─► /dev/shm ring   │   │ events API   │
│ 相機+紅光(外罩外) │◄─┤ inspector: L0–L3 幾何 → L4 分類 → event  │──►│ dashboard    │
│ SDCP WebSocket   │◄─┤ advisor: 瑕疵類→參數→下發 (vigil-phrozen) │   │ R2(資料集)  │
│                  │  │ uploader / agent(既有)                  │   │ Neon PG      │
└──────────────────┘  └──────────────────────────────────────────┘   └──────────────┘
                      ┌─ 離線訓練管線(不在邊緣)──────────────────────────────────┐
                      │ capture → 弱標註 → 人工覆核(Roboflow) → dataset          │
                      │ → EfficientNet-B0 訓練 + HPO → 評估 → ONNX → 部署回 Jetson │
                      └────────────────────────────────────────────────────────────┘
```

### 3.2 邊緣模組拆解(`inspector` 服務)
建議把 `inspector` 做成套件而非單檔:

| 模組 | 職責 | 層 |
|---|---|---|
| `frame_source.py` | 從 `/dev/shm` ring 讀最新完整 frame(~5fps) | 前級 |
| `cycle_lock.py` | motion signal → 自相關/峰距 → 週期+相位+信心 | L0 |
| `capture.py` | dwell 中位數 → 一張 layer frame/週期 | 前級 |
| `preprocess.py` | plate ROI crop + **固定 3A 正規化** + resize | 共用 |
| `geometry.py` | 剪影/面積/成長性 → L1/L2/L3 verdict + 弱標籤 | L1–L3 |
| `classifier.py` | ONNX Runtime 載入 EfficientNet-B0,五分類推論 | **L4 = a1.2 模型** |
| `debounce.py` | 連續 k=3 層一致才 raise | 尾段 |
| `events.py` | 寫本地 SQLite queue + 裁切縮圖 | 尾段 |

### 3.3 vigil-phrozen 閉環模組(`advisor`)

## 4. 實作方法 — 五條工作線(WS)

以「115/09 過關」為終點反推,五條並行工作線:

### WS1｜資料集(補到每類 ≥300 張測試)— 🔴 最卡
現況 abnormal 僅 26 張,缺口 10 倍以上。步驟:

1. **四類重標規範**:先寫一頁標註準則(每類的判準、邊界案例、反光 vs 真瑕疵怎麼分),回溯重標既有影像從二元 → 五類。這是 §2.2 的前置,不做全線卡住。
2. **量產原始影像**:vigil-phrozen 每次列印自動存全套 layer frames(phase-locked,已對齊)。一次 4–8h 列印產出數百層。
3. **誘發失敗補瑕疵類**(依 RESEARCH.md §4.2):
   | 類別 | 誘發方式 | 預期起始 |
   |---|---|---|
   | 翹邊/脫層 | 底曝×0.5 / 底層 1–2 層 / 離型劑 | 前 10% 層 |
   | 缺層 | 曝光×0.6 / 零過渡層 / 抬升速度×2 | 中段 |
   | 材料不足 | 樹脂液位刻意調低 | 隨機 |
   | 反射過曝 | 刻意變光源角度/強度、on-axis 反光 | 拍攝時製造 |
4. **幾何自動弱標註**:L0–L3 對每張 frame 預標,人工只覆核(Roboflow),大幅省工。
5. **ground truth**:韌體層索引 + Z 馬達電流自動標失敗起始層(Phrozen 機板可取,比人工硬)。
6. **切分**:train/val/test 實體目錄分離,`records.csv` 記錄歸屬。
   > ⚠️ **測試集獨立性**:同一次列印的相鄰 frame 高度相關,300 張若全來自同一列印,統計意義薄弱。**測試集要跨多次列印/多幾何/多樹脂抽樣**,並確保 test 的「列印場次」與 train 完全不重疊(不只影像不重疊)。這點要寫進驗證計畫書,查證時會被問。

**WS1 產出:** 五類各 ≥300 張測試 + ≥100 筆平衡樣本、`records.csv`、標註準則文件、環境架設照片(補 a1.1 的 B3)。

### WS2｜模型訓練 + 參數優化(D2 + ACC/FPR/FNR)

**2.1 架構**:torchvision `efficientnet_b0(weights=IMAGENET1K)`,換 5-way 分類頭。授權 BSD-3,無 copyleft。

**2.2 訓練 config(`configs/effnet_b0.yaml`)**
```yaml
model: efficientnet_b0
num_classes: 5           # normal + 翹邊/缺層/反射過曝/材料不足
imgsz: 224
batch: 32                # 固定 batch size(a1.2 測試條件)
seed: 42
optimizer: adamw
lr: 3.0e-4
scheduler: cosine
warmup_epochs: 3
epochs: 100
patience: 25             # early stopping
freeze_backbone_epochs: 5
loss: focal              # 對抗類別不平衡 → 壓 FNR
focal_gamma: 2.0
class_weights: balanced
augment:                 # 溫和增強(frame 已對齊,勿過度幾何變換)
  brightness: 0.1
  hflip: 0.5
  rotate_deg: 5
preprocess:              # 訓練/測試/上線一致
  roi_crop: true
  three_a_normalize: true
```

**2.3 參數優化流程(D2 要的「參數優化」)**:用 `hpo.py`(Optuna)搜尋 `{lr, weight_decay, focal_gamma, freeze_epochs, aug 強度}`,以 **val 的 FNR 為主目標**(次目標 ACC)。保留搜尋紀錄當 D2 佐證。

**2.4 攻 FNR ≤ 10%(唯一未達標)**:
- Focal loss + class-balanced weights,懲罰漏判。
- 決策閾值偏召回:normal 的判定門檻調高(寧可多報瑕疵,再由 debounce/反射過曝類濾除)。
- 混合標籤全圖是主要 FN 來源(現況 1 筆 FN 信心 0.99997)→ 改用 plate-ROI crop + 四類明確化,消除「有無層紋」的模糊。
- **系統級安全網(非模型級)**:上線時 debounce 要求連續 k 層一致,單張漏判不致漏掉整次失敗。但 a1.2 的 FNR 量在**模型單張**上,所以模型本身仍須 ≤10%,debounce 只是額外保險。

**2.5 評估(`evaluate.py`)**:輸出 5×5 混淆矩陣、二元塌縮 2×2、每類 precision/recall、ACC/FPR/FNR,跑在 test 集(每類 ≥300)。這份報告 = a1.2 的核心佐證。

### WS3｜可部署推論流程(D3 + Jetson)
1. `export_onnx.py`:best.pt → `model.onnx`(固定 batch、opset 穩定版)。
2. Jetson Orin Nano:ONNX Runtime(或 TensorRT)載入,`classifier.py` 呼叫。
3. 量測推論延遲(EfficientNet-B0 在 Orin Nano 應為個位數 ms)。
4. 前處理(crop + 3A + resize)與訓練用**同一份 `preprocess.py`**,杜絕 train/serve skew。
5. **主權模型**:frame 不出廠,對齊 a1.3 與牙科客戶訴求。

### WS4｜閉環參數自適應(≤5 秒)
1. **瑕疵類 → 動作映射**(`advisor/mapping.py`):
   | 類別 | 動作 | 說明 |
   |---|---|---|
   | 翹邊/脫層 | 底曝↑、抬升速度↓ | 承 `agent_framework.py` 規則 |
   | 缺層 | 曝光↑、加過渡層 | |
   | 反射過曝 | **不動作 / 抑制警報** | 這是假陽性類,壓 FPR |
   | 材料不足 | 暫停 + 通知補料 | 參數改不了,需人工 |
2. **落地分階段**(對齊「先偵測後行動」):
   - 建議式(先做):偵測→建議→通知,量「偵測→建議」延遲。
   - 半閉環:偵測→暫停→一鍵套用。
   - 全閉環:自動調參/中止,opt-in per machine,絕不預設。
3. **延遲量測**(`advisor/latency.py`):時間戳記 t_detect / t_suggest / t_apply,n=20 連續列印取平均。**建議式即可先量到 ≤5 秒的偵測→建議段**,爭取時程;5 秒對「模型推論(ms)+ 規則查表(ms)+ SDCP 下發(<1s)」非常寬裕。

### WS5｜調整後成功率 +20% 實驗
1. **實驗設計**:誘發**邊際失敗條件**(如底曝略低,使基線成功率約 50–60%),讓 AI 介入有空間展現。
2. **對照組**:同模型、同樹脂、同環境,A 組(無 AI)vs B 組(AI 偵測早期脫層徵兆 → 調整底曝/抬升 → 挽救)。
3. **規模**:≥50 次列印、同模型重複 ≥10 次,材料相同,排除斷電/操作失誤。
4. **定義先寫死**:「提升 ≥20%」是相對還是絕對百分點,要在驗證計畫書先定義(建議定為相對提升,並設計誘發使基線落在 60% 左右 → AI 達 80%+ 即達標),避免查證時委員自由心證。

## 7. 風險

| 風險 | 緩解 |
|---|---|
| 🔴 300 張/類趕不及 | 誘發列印可在數天內量產瑕疵 frame;幾何弱標註省覆核工;測試集跨場次抽樣確保品質 |
| 🔴 FNR 卡在 10% 上 | focal loss + 閾值偏召回 + crop 消除混合標籤 + HPO 以 FNR 為主目標 |
| 🟠 反射過曝樣本難蒐 | 刻意變光源角度/強度製造;這類本就要當假陽性學 |
| 🟠 閉環需機台整合 | vigil-phrozen 走 DS-Online SDCP;先建議式量延遲爭取時程 |
| 🟠 成功率實驗跑不完 50 次 | 三台機並行;誘發邊際條件縮短單次可判時間 |
| 🟡 train/serve 前處理不一致 | crop+3A 共用同一 `preprocess.py`,訓練與 Jetson 上線同一份 |
| 🟡 光學不可分 | Phase 0 光學閘門先過(DETACHMENT.md §3) |
