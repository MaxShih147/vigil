## 0. 一頁執行摘要

A1 要的是一個「**能看著列印、判斷成敗、並回饋調整**」的 AI 實時品質監控系統,並用 **ACC≥90% / FPR≤10% / FNR≤10%**、四類主瑕疵(翹邊、缺層、反射過曝、材料不足)、每類 ≥300 張測試影像、參數自適應 ≤5 秒、調整後成功率 +20%、巡檢工時 −30% 等硬指標驗收。

vigil 原本設計為「相機掛在機器外、不整合、幾何優先」的**通用**檢測盒。它的資料管線(每層一張已對齊的影像)、光學設計、邊緣部署,恰好補上 A1 現在最大的三個缺口:**樣本數不足(現況 26 張 vs 需求 300 張/類)**、**固定硬體佐證**、**主權模型邊緣部署**。

因此本計畫採**雙 profile 策略**:
- **vigil-phrozen**(計畫載具,現在做):允許整合 Phrozen 牙科機台,才做得出閉環調整與工時降幅 → **這是通過 a1.2 / a1.3 的最小可行系統**。
- **vigil-generic**(未來產品,擴充):維持「不整合、任意機台」的通用檢測盒 → **這是計畫成果的商業化延伸**。

一句話:**用 vigil 的資料與偵測管線去餵養並驗收 A1 的自研模型;先把 Phrozen 自家機台做到查核點過關,再把同一套幾何管線產品化成通用盒。**

## 1. 計畫定位:為什麼是 vigil,以及雙軌策略

### 1.1 計畫優先原則
本文件所有設計決策的第一排序準則是:**能不能在查核時點交出符合統計基準的佐證**。任何「技術上更漂亮但趕不上查核點」的路線一律降級。查核點的統計基準(樣本數、公式定義、測試條件)就是驗收規格,不是參考。

### 1.2 vigil 原始設計與 A1 的張力
vigil 的產品哲學是「幾何優先、不整合機台、適用任意機器」,並主張「L1(detachment)就是產品、edge 永遠不需要模型」。但 A1 綁死要一個**訓練出來的四類瑕疵模型**、要**閉環參數調整**、要**工時/材料降幅**——這些都需要與機台雙向溝通,且需要一個學習型模型。

**化解方式 = 雙 profile。** A+ 計畫的標的是 Phrozen 自家牙科印表機,你握有 DS-Online 的 `printer_control` / SDCP WebSocket 與韌體,整合是拿得到的。於是把 vigil 拆成兩個部署 profile,共用同一套程式與資料模型:

| Profile | 定位 | 是否整合機台 | 對應 |
|---|---|---|---|
| **vigil-phrozen** | 計畫載具 / 查核點佐證 | 是(SDCP / printer_control) | a1.2 閉環、a1.3 工時降幅 |
| **vigil-generic** | 未來通用產品 | 否(幾何優先、任意機台) | 計畫結束後之商業化擴充 |

兩者差別**只在最上層的「動作/整合」與部署設定**,底層(光學、cycle lock、phase-locked capture、四類偵測、資料管線)完全共用。這確保計畫投入的每一分工都能延續成產品。

## 3. vigil 產品架構(作為通過 A1 的載具)

### 3.1 核心洞察(承 PRODUCT.md §4)
樹脂印表機是節拍器:每層重複「抬起→停頓→下降→曝光」。若在**每個週期同一相位**(抬到頂、樹脂滴乾靜止時)取一張 frame,得到的影像堆疊**天生對齊**——不需對位。frame N 與 N−1 只差一層 0.05mm,任何有意義的差異都是訊號。

**這對 A1 的直接價值:** 每個列印週期自動產出一張「已對齊、有時間戳、可自動標註」的 layer frame。**這就是 A1 生不出 300 張/類資料集的解法**(§5)。

### 3.2 偵測階梯 L0–L4 ↔ A1 四類瑕疵
vigil 的五層偵測階梯,同時扮演「幾何觸發器」與「A1 分類模型的資料前級」:

| 層 | 定義 | 跑在哪 | A1 角色 |
|---|---|---|---|
| **L0** | 機器還在照週期運轉嗎 | edge | job 生命週期、資料切分依據 |
| **L1** | 平台下還掛著東西嗎(脫層/翹邊) | edge, OpenCV | **觸發器**:抓到疑似 → 標記 frame |
| **L2** | 剪影是否單調成長(缺層) | edge, OpenCV | **觸發器**:成長停滯 → 標記 frame |
| **L3** | 觀察 vs 切片檔預期截面 | edge + slice-parser | 幾何 ground truth(輔助標註) |
| **L4** | **四類瑕疵分類 + 解釋**(EfficientNet-B0 + VLM) | Jetson 本地 / cloud | **這就是 A1 的自研辨識模型** |

**關鍵對應:A1 要驗收的那個「AI 辨識模型」= vigil 的 L4。** L0–L3(幾何)不是要取代模型,而是**當 L4 的觸發器與自動標註器**——幾何層挑出可疑 frame、給出弱標籤,大幅降低人工標註成本,讓 300 張/類變得可達。

### 3.3 系統架構(三區,承 PRODUCT.md §6)
- **Edge(盒子):** Raspberry Pi 5(base)或 **Jetson Orin Nano(judge/主權模型 tier)**。服務:`recorder`、`uploader`、`agent`(已存在)+ `inspector`(新,跑 L0–L4)+ `slice-parser`(新)。
- **Cloud:** Next.js on Vercel + Postgres(Neon)+ R2 物件儲存 + 事件 API。
- **Client:** 儀表板、機台旁 kiosk 螢幕、手機通知。

**vigil-phrozen 額外一條線:** `inspector` ↔ DS-Online `printer_control`(SDCP WebSocket)雙向通道,用於 a1.2 的閉環參數調整。vigil-generic 不啟用這條線。

## 4. 四類主瑕疵:定義與偵測方式對照

A1 綁死四類,這是三邊(計畫書 / vigil ladder / SLA 標註)目前**最不一致、最該先統一**的地方。以下為建議的統一定義:

| A1 類別 | 現象定義 | 主偵測層 | 偵測方式 | ground truth 來源 |
|---|---|---|---|---|
| **翹邊 / 脫層** | 件從建板脫落或邊緣翹起,剪影面積崩塌 | **L1** | 剪影面積 < 0.3 × 歷史最大值,持續 k 層 | 韌體層索引 + Z 馬達電流驟降 |
| **缺層 / 分層剝離** | 平台上升但剪影停止成長 | **L2** | 面積單調性中斷偵測 | 目視標記 + 切片預期截面(L3) |
| **反射過曝** | 反光/過曝造成假影,非真實瑕疵 | **L4** | VLM 區分 failure vs reflection;固定 3A 正規化後判定 | 人工標註(反光為負類) |
| **材料不足** | 樹脂液面過低,件表面殘缺、局部未成型 | **L4** + L2 | 局部剪影缺塊 + 分類模型 | 人工標註 + 液位感測(可選) |

**設計決策:**
- **翹邊、缺層**由幾何層(L1/L2)直接偵測 → 快、可解釋、edge 上 ms 級。
- **反射過曝、材料不足**需要語意判斷 → 交給 L4 分類模型。
- **四類的最終「分類標籤 + 信心度」統一由 L4 輸出**,以符合 a1.2 用單一模型跑 ACC/FPR/FNR 的驗收方式;幾何層負責觸發與弱標籤。
- **反射過曝被列為獨立一類非常關鍵**:它是壓低 FPR 的主戰場(把反光誤判成瑕疵是最常見的假陽性),而 vigil L4 本來就設計要「區分 failure vs reflection」,天然吻合。

**標註規範遷移:** 現行 SLA repo 為二元(`NoDefect`/`Defects`/`Row`/`NoRow`),需**重新定義為四類並回溯標註**。這是 a1.2(各類 ≥100 筆)的前置,不做會直接卡住。

## 5. 資料集計畫(補到 300 張/類,這是 a1.2 最大缺口)

### 5.1 缺口
a1.2 要求每類 ≥300 張測試影像、各類 ≥100 筆平衡樣本;現況 test 集僅 abnormal 26 張。**差距 10 倍以上。**

### 5.2 vigil 資料管線如何補
vigil 的 **phase-locked capture** 每個列印週期產出一張已對齊 layer frame。一次 4–8 小時的列印 = 數百到數千層 = 數百張同機位、同光源、已對齊的影像。**幾層策略:**

1. **量產原始影像:** vigil-phrozen 每跑一次列印自動存下全套 layer frames(這是 vigil 免費副產品,PRODUCT.md §4)。
2. **自動弱標註:** L0–L3 幾何層對每張 frame 給出弱標籤(正常/翹邊/缺層/疑似),人工只需覆核而非從零標。
3. **誘發失敗補齊瑕疵類:** 依 RESEARCH.md §4.2 誘發協定,刻意製造四類失敗(降底曝、減底層、離型劑、降支撐密度、液位不足),讓稀有的瑕疵類也能湊到 300 張。
4. **ground truth:** 用韌體層索引 + Z 馬達電流(Phrozen 機板可取)自動標記失敗起始層,比人工更硬(RESEARCH.md §4.3)。

### 5.3 資料集 schema(供 A1 佐證與未來 dataset 釋出)
每張 layer frame 附:`job_id`、`layer`、`machine_slug`、`resin_name`、`dental_mode`、`class_label`(四類之一)、`ground_truth_source`、`capture_hw_config`(固定硬體佐證)、`preprocess`(3A 參數)、`split`(train/val/test 不重疊)。

**這份 schema 同時滿足:** a1.2 的統計基準、a1.1 三份驗證計畫書的測試條件、RESEARCH.md 的 *vigil-resin-failures* dataset 釋出。

### 5.4 3A 校正(回應 a1.1 追蹤表 B5)
硬體端**鎖定曝光/白平衡/對焦**(vigil 硬需求,保證 frame 可比較);推論前再加一個**固定參數的 3A 正規化**步驟(對齊 a1.2 測試條件「影像經 3A 校正」)。兩者不衝突:一個在拍攝、一個在前處理。**需在 `inspector` pipeline 實作此步驟,否則驗證計畫書的測試條件要據實改寫為「鎖定曝光」。**

## 7. 閉環參數調整(vigil-phrozen,a1.2 的 ≤5 秒)

### 7.1 需求
a1.2 要「偵測到瑕疵 → 出現參數建議 → 調整完成 ≤ 5 秒」,且「調整後成功率 +20%」。這需要與機台雙向溝通,是 vigil-generic 刻意不做的部分。

### 7.2 vigil-phrozen 的閉環
利用 DS-Online 既有能力串起來:

```
inspector 偵測瑕疵(L1/L2/L4)
  → 產生參數建議(曝光時間、抬升速度、Light-off Delay… 對應 DS-Online 79 項參數)
  → 經 printer_control / SDCP WebSocket 下發
  → 機台調整 / 或暫停等待確認
  → 記錄「AI 介入前後」對照(供成功率 +20% 佐證)
```

### 7.3 分階段落地(對齊「先偵測、後行動」的安全原則)
- **7.3.1 建議式(先做):** 只出參數建議 + 通知,人工確認後套用。可先量測「偵測→建議」延遲。
- **7.3.2 半閉環:** 偵測 → 暫停列印 → 推建議 → 一鍵套用續印。
- **7.3.3 全閉環:** 偵測 → 自動調參/中止。opt-in per machine,絕不預設(承 PRODUCT.md §7 auto-abort 警語)。

**≤5 秒的量測**取「偵測到瑕疵」到「參數調整完成」的時間差,n=20 次連續列印取平均。**建議式即可先量到「偵測→建議」段**,爭取查核點時程。

## 8. 效益量測與基線留存(a1.3,現在就要啟動)

| 指標 | 目標 | 量測方式 | 立即動作 |
|---|---|---|---|
| 巡檢工時 | −30% | 導入前每日巡檢工時 vs 導入後 | 🔴 **現在開始記錄導入前基線** |
| 即時處理人力 | −15% | 異常事件人工介入次數/時數 | 🔴 同上 |
| 材料浪費 | −20% | 廢件材料損耗率(倉管領用/產線耗用) | 🔴 用既有耗材編列表當基線起點 |
| 調整後成功率 | +20% | AI 介入 vs 未介入之受控列印對照 | 設計受控實驗,材料/環境固定 |

**沒有導入前基線就算不出降幅**,且基線必須是導入前留存的。這是本計畫**最容易因拖延而失敗**的部分,獨立列為即刻啟動項。

## 9. 最小可行系統(MVP)定義

MVP 的判準是「**剛好能讓 a1.2(115/09)與 a1.3(115/12)過關**」,不多做。

### 9.1 MVP 範圍(vigil-phrozen,對齊 a1.2 / a1.3)
| 元件 | MVP 內容 | 對應查核點 |
|---|---|---|
| 光學/擷取 | 固定治具 + 鎖定曝光 + 固定 3A 正規化 + phase-locked capture | a1.2 測試條件、a1.1 環境照片 |
| 幾何觸發 | L0 + L1 + L2(OpenCV) | 四類中的翹邊/缺層 + 自動弱標註 |
| 分類模型 | EfficientNet-B0 四類,達 ACC≥90/FPR≤10/**FNR≤10** | a1.2 硬指標 |
| 資料集 | 四類各 ≥300 張測試、≥100 筆平衡(靠 §5 補) | a1.2 統計基準 |
| 閉環 | **建議式**(7.3.1),量到「偵測→建議」≤5 秒 | a1.2 參數自適應 |
| 部署 | Jetson Orin Nano 本地推論 + 授權相容性文件 | a1.3 主權模型/授權 |
| 效益 | 巡檢工時/材料基線 + 受控實驗成功率 +20% | a1.3 降幅、a1.2 成功率 |

### 9.2 MVP 刻意不做(降級到擴充階段)
- L3 切片比對(排 Phase 5 / a3.x)。
- 全閉環自動中止(安全原則,opt-in 後做)。
- vigil-generic 通用產品化。
- A2 排程、A4 失效預知(其他分項,非 A1)。

## 10. 擴充性藍圖(計畫成立之後)

計畫投入的每一塊都設計成可延伸,不是拋棄式佐證:

| 擴充方向 | 承接的 MVP 資產 | 對應 |
|---|---|---|
| **vigil-generic 通用產品** | 同一套光學 + cycle lock + 幾何 ladder,拿掉整合 | 商業化;PRODUCT.md §11 泛化 |
| **L3 切片比對(護城河)** | slice-parser + 既有 layer frame | 印錯檔/缺區塊偵測 |
| **更多失敗模式** | 四類 → 擴充失敗分類 | A4 失效預知(a4.1) |

| **dataset 釋出** | §5.3 schema | RESEARCH.md、學術發表 |

**設計原則:MVP 的資料 schema、verdict 契約、幾何管線,都以「之後要泛化」為前提設計**,所以 vigil-phrozen 的每一份佐證都能無縫變成 vigil-generic 的產品能力。

## 12. 風險與緩解(整合 A+ 追蹤表 + vigil 風險)

| 風險 | 影響查核點 | 緩解 |
|---|---|---|
| 🔴 瑕疵樣本嚴重不足(26 vs 300) | a1.2 | vigil phase-locked 量產 + 誘發失敗 + 幾何弱標註(§5) |
| 🔴 標註體系不對應四類 | a1.2 | 現在重新定義四類並回溯標註(§4) |
| 🔴 導入前基線未留存 | a1.3 | 立刻啟動巡檢工時/材料記錄(§8) |
| 🔴 FNR 11.54% > 10% | a1.2 | 補樣本 + 閾值偏召回 + 拆混合標籤(§6.4) |
| 🟠 閉環需整合機台 | a1.2 ≤5 秒 | vigil-phrozen 走 DS-Online;先建議式量測(§7) |
| 🟠 AGPL 授權 | a1.1/a1.3 | 全面改 EfficientNet-B0,補 LICENSE/NOTICE(§6.2) |
| 🟠 3A 未實作 | a1.2 條件 | pipeline 加固定 3A 正規化 或 據實改寫測試條件(§5.4) |
| 🟡 光學可行性(影像不可分) | 全部 | vigil Phase 0 光學閘門先過(DETACHMENT.md §3) |
| 🟡 每裝置差異 | 泛化 | baseline 每裝置學習,一鍵重學 |

**光學可行性是所有東西的閘門**:若相機根本看不出樹脂列印失敗,再多軟體都沒用。vigil Phase 0(手機/webcam + 紅光,誘發一次失敗,人眼能指出失敗層)必須最先過。
